## 第二步：临时 XML 检查模式（临时确认模式）

架构要点：XML 解析全在前端（fast-xml-parser），Rust 只返回原始文本；持久化唯一入口是 `documents.write`（save_local_file）。临时模式只新增"读文件"能力，构建**纯内存**的合成 StoredModelRecord，完全不触碰存储。

### 后端（src-tauri）
- `Cargo.toml`：加 `tauri-plugin-dialog = "2"`；`lib.rs`：注册 `.plugin(tauri_plugin_dialog::init())`；`capabilities/default.json`：加 `dialog:default`。
- 新命令 `read_xml_file(path) -> { path, file_name, content }`（lib.rs）：`std::fs::read_to_string` + 去 BOM，错误带路径；**纯读取，不写任何存储**（无 UNC 凭据处理，本地文件场景）。

### 前端
- `tauri-app/package.json`：安装 `@tauri-apps/plugin-dialog`。
- **app.service.ts**：
  - 新增 `TempSpecSession`（filePath/fileName/kind/lightSlot/合成 record/原始 inspection XML）+ `tempSession` 字段 + `tempModeChanged$` Subject（镜像现有 `activeSelectionChanged$` 模式，纯字段无 signal）。
  - `loadTempSpec(path)`：invoke `read_xml_file` → 用现有 parser 判定类型（`pixel.Light_Setting` → LightSpec；`pixel.GPNODE` → InspectionSpec；否则报错）→ 构建合成 `StoredModelRecord`（machine=`{id:'', name:'TEMP'}`，modelName=文件名；FM1 放数据，FM2/BM 空桩；InspectionSpec 用现有 `buildInspectionGroups` 解析，LightSpec 用 `buildAlignment`）→ 只改内存 + 发事件。
  - `loadTempDictionary(kind)`：补读 SpecParameter.xml / SpecTreeNode.xml，用现有 `parseStringDictionary`/`parseNodeDictionaries` 重建 groups 解析出名称/颜色。
  - `exitTempMode()`：清空并发事件。全程零 `documents` 调用。

### UI（对应截图两处红框 + 两个页面入口）
- **app.component.ts**（左上 MODEL/LOT 栏）：订阅 `tempModeChanged$`，临时模式时 MODEL 显示文件名 + 琥珀色 `TEMP` 徽标（复用 legacy-warning 配色 #5a4a2d/#ffd88a），标记当前处于临时确认模式。
- **parameter-config.component.html/ts（TEACH 右上 model-bar）**：临时模式时 model-name 显示 `TEMP / 文件名` + 徽标；**隐藏 Save Local / Reload**；新增「加载 XML」「退出临时」按钮；InspectionSpec 时附 LIGHT 槽位选择（Light-1/2/3）与两个可选字典加载按钮。ngOnInit 优先采用 tempSession，订阅事件实时切换。
- **calibration-light.component.ts（CALIBRATE model-bar）**：同样加「加载 XML」「退出临时」+ 徽标；临时 record 的 lightSpec 直接喂给现有 `getLightChannels` 渲染 channel 表；**隐藏 GV 表**（GV 是手动测量数据，与 spec 无关且会触发存储），不加载 gvStore。
- **只读保护**：临时模式下参数表格 `[disabled]="busy || tempMode"`；`rememberSelection` 跳过持久化（避免写 ui/teach-selection.json）；TEACH 的 Save Local / Reload 与 CALIBRATE 的 GV 保存天然被隐藏/禁用，确保**任何数据库写入路径都不可达**。
