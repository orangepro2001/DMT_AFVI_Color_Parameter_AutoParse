## 1. 背景与目标

AFVI 检查机在标定阶段需要知道：**给定某个颜色三个角度的光照强度组合，被测物返回的
GV（灰度值）是多少**；标定员目前靠经验试凑。本模块把这件事变成可计算的：

- **正向**：输入某颜色的 `0° / 30° / 60°` 三路光强 → 输出预测 GV。
- **反向**：输入目标 GV → 输出若干组可行的三路光强组合（按偏好排序）。

**拟合方式（已定）**：离线用 Python 做 DOE 回归，算出多变量二次多项式响应面模型的
10 个系数；把这 10 个常数交给 UI，UI 只做多项式求值（微秒级，无需任何计算库）。

**建模单位（修订 2026-09-23）**：按**颜色分别建模**——Red/Green/Blue 是物理独立的
LED 与检测通道，各自走一套完整的"标定 → BBD 19 点 → 拟合"，共 3 个模型。
White 不做（用户明确倾向不用：White 是自混合光，比例不可控）。

**量程标定（修订 2026-09-23，D6–D8）**：实测发现部分轴强度 1 即 GV 240+，
固定 0~1024 档位会产出全 255 的零信息数据。因此采样前先逐轴标定强度窗口，
档位从窗口内取——**档位是标定产物，不是写死的常量**（详见 01 §2）。

### 为什么这样做

| 方案 | 结论 |
|---|---|
| UI 里跑拟合 | ❌ 前端无法做回归，且引入不必要的依赖 |
| UI 里硬编码 10 个系数 | ✅ 求值只是 10 次乘加，zoneless CD 下实时滑条拖动无压力 |
| Rust 侧实现 | ⚠️ 只做 3 变量多项式没必要，除非之后要上神经网络 |
| 固定 0~1024 三档 | ❌ 饱和轴上 2/3 运行是平台（全 255），平方项不可估——已被 D6 取代 |

## 2. 范围

**In scope**
- 每颜色（R/G/B）的三路光强 ↔ GV **静态映射建模**（每色独立：0° / 30° / 60°）。
- **量程标定**：逐轴强度窗口扫描、档位建议、饱和检测与迭代重标定。
- 正向预测、反向推荐、结果展示与持久化。

**Out of scope（本计划不做，需另行决策）**
- 跨颜色联合建模（R/G/B 放进同一个响应面）——变量 3→9，采样量指数上升，
  且三通道物理独立、无交互证据，按色独立建模已够用。
- 回写生产 XML / 直接控制光源硬件（调曝光/增益属于硬件操作，由人工执行）。
- 温度、镜头等其它影响 GV 的因素（假设采集期间恒定）。

## 3. 阶段依赖与数据流

```
阶段一 量程标定+DOE 采样 ──▶ 阶段二 拟合 ──▶ 阶段三 UI
  (档位表+57点数据)         (light-models.json)  (Angular)
```

```
Plan/                     tools/light-analyse/                 tauri-app/src/app/
  ├─ 01_DOE_SAMPLING.md
  ├─ 02_RSM_FITTING.md
  └─ 03_LIGHT_ANALYSE_UI.md
                          ├─ doe_design.py   ──▶ samples.xlsx（Excel 载体）
                          ├─ light-sampling-guide.html       （向导载体：标定+采样+导出）
                          └─ fit_model.py    ──▶ light-models.json（每色 1 模型 ×3）
                                                               └─ light-analyse.component.ts
```

- 阶段三**不阻塞**于阶段一、二：可先用阶段二输出的**占位系数**（全 0 或理论值）把 UI 与
  单元测试框架搭起来，真实系数到位后直接替换 JSON 即可。
- 阶段一、二可合并为一次"标定"，但文件分开是为了让现场采数的人只看 01，做分析的人只看 02。
- **档位表（levels）是贯穿三个阶段的公共数据**：向导生成/消费、Excel 记录、
  拟合反推校验、UI 用作输入边界。它属于模型的一部分，随 `light-models.json` 一起交付。

## 4. 关键决策（已定 / 待确认）

### 已定
| # | 决策 | 说明 |
|---|---|---|
| D1 | 采用 **二次响应面模型**（含交互项与平方项），**按活跃轴动态定项** | k=3 → 10 系数；禁用轴降维（k=2 → 6 项），见 01 §2.5 / 02 |
| D2 | 采用 **Box-Behnken 15 点** 作为基础采样方案 | 见 01 的采样点数分析 |
| D3 | 拟合在**编码变量**（−1/0/+1）上做，再换算回实际值 | 数值稳定性，见 02 |
| D4 | 系数以 **JSON 文件**交付给 UI，不在代码里写死 | 见 03 的数据源方案 |
| D5 | 反推用 **网格搜索 + 偏好排序**，返回 Top-N 候选 | 3 变量 1 目标必为欠定方程，见 03 |
| D6 | **量程标定**：每 颜色×角度（9 轴）独立三档，不再固定 0/512/1024 | 固定档位在饱和轴上产出全 255 的零信息数据（实测：强度 1 即 GV 240+）；档位窗口内的窄量程与全量程在数学上等价（编码吸收缩放）。见 01 §2 |
| D7 | 采样中检测到饱和 → **整色作废重测** | 档位变更 = 该色坐标系更换，新旧数据不能混入同一回归；旧点强度落在新窗口外本就是截断废点。见 01 §2.4 |
| D8 | 扫描自动建议档位的目标 GV 窗口 = **60 ~ 200**（可改） | 避开暗水平噪声(<50)与饱和压平区(>230)，中档≈130 上下各留 ~120 counts 漂移余量。见 01 §2.4 |
| D9 | White 光**不做**（用户倾向） | White 是自混合的柔和光，比例不可控；未来若加，走同一套流程即可 |

## 6. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **光轴响应窗口异常**（强度 1 即 GV 240+，固定档位下大面积饱和） | 固定 0~1024 采样产出全 255 的零信息数据，模型不可用 | **D6 量程标定**（Plan/01 §2）：采样前逐轴扫描定档位；采样中饱和监视 + 整色重测迭代 |
| 标定后窗口过窄（high−low < 10 甚至仅两档） | 模型分辨率差 / 单轴二次项不可估 | 优先调曝光/增益拉宽窗口；否则该轴固定值退化为 2 因子设计（Plan/01 §2.5），并在模型中显著标注假设 |
| GV 存在明显噪声/读数抖动 | 拟合 R² 上不去 | 每点读数取 3 次中位数；中心点重复 3 次估纯误差 |
| 三路光不是线性叠加（互相干扰） | 交互项系数大，甚至非线性更强 | 阶段二看残差图；若不足则升级到三次项或增加点数 |
| 设备之间存在个体差异 | 一套系数只对一台机器有效 | 明确"一台机器一套模型"，模型文件与 machineId 绑定（见 03） |
| 光源长时间点亮导致漂移 | 越晚测的点偏差越大；标定时刻与采样时刻窗口漂移 | 运行序随机化 + 每 5 点回测一次中心点；采样中饱和监视兜底 |
| 反推解不唯一让人困惑 | 标定员不信任结果 | UI 明确给出"偏好排序"与每个候选的预期 GV 误差 |

## 7. 验收（整体）

- [ ] 三个阶段的文件都有对应的**产出物落盘**（Excel / JSON / 组件）。
- [ ] **档位表（levels）在向导 / Excel / `light-models.json` 三处一致**（交叉校验通过，
  任一处被手改都能被另外两处发现）。
- [ ] Python 拟合脚本可重复运行，输入同一个 Excel 得到同一份 JSON（确定性）。
- [ ] 拟合端对窄量程模型（如档位 0/1/2）与默认量程模型给出一致的结果结构（回归测试）。
- [ ] UI 的正向预测与 Python 对同一输入的结果误差 < 1e-6。
- [ ] 反推给出的候选，回代正向公式后 GV 误差 ≤ 目标允许带。
- [ ] 不引入新的硬编码路径（遵循项目既有规则：配置存数据库/JSON）。
