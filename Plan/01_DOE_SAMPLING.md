# 阶段一 — 量程标定与 DOE 采样

> 目标：先为每个「颜色×角度」轴找到**有响应变化的强度窗口**，再用**最少的打光次数**
> 在窗口内完成二次响应面采样，产出向导/Excel 双载体。

对应总纲决策：D2 / D6 / D7 / D8 / Q1。产出：`tools/light-analyse/` 下的档位表、
`samples.xlsx`、`light-sampling-guide.html` 采样向导与回填后的实测数据。

> **修订记录（2026-09-23）**：本文件曾把三档固定为 0/512/1024。实测反馈推翻了该假设
> （详见 §2.1），本版引入"量程标定"作为新的第一阶段，并把档位改为**按轴可配置**。

## 1. 变量与响应定义

| 符号 | 含义 | 名义范围 | 实际范围 | 备注 |
|---|---|---|---|---|
| x₁ | 0° 光（同轴/동축）强度 | 0 ~ 1024 | **由 §2 标定** | 来自 `LightSpec.xml` 的 Channel `Value` |
| x₂ | 30° 光强度 | 0 ~ 1024 | **由 §2 标定** | 同上 |
| x₃ | 60° 光强度 | 0 ~ 1024 | **由 §2 标定** | 同上 |
| Y | 实测 GV 灰度值 | 0 ~ 255（待确认） | — | 人工测量，**不存在于任何 XML** |

- "名义范围"是驱动器接受的数值；"实际范围"是 **GV 有变化的窗口**，才是建模有效的定义域。
- 共 3 色 × 3 角度 = **9 个轴**，每轴独立标定（理由见 §2.4）。

**变量来源校验（做一遍，别凭印象）**：从已采集的模型快照里读出该型号实际启用的通道与角度，
确认"0° / 30° / 60°"这三路确实存在、且各自的 `Value` 上限是 1024。

```
app-data/models/<machineId>/<model>.json
  → hosts.<FM1|FM2|BM>.lightSpec.Light_Setting.LightSet.Page[n].Channel
      @Color / @Angle / @Value / @Enable
```

（前端已有现成解析逻辑可复用：`export_excel.rs` 的 `light_axis_texts`。）

**编码变量**（拟合与设计表用编码值，避免量纲病态）：

```
x_coded = (x_real − 中档) / 半程        // 等距三档时恒为 (v − mid) / half ∈ {−1, 0, +1}
```

> 半程 = (high − low) / 2。**中档必须是算术中点**（mid = (low+high)/2），原因见 §2.4。

## 2. 量程标定（Range Calibration）— 为什么必须放弃固定 0~1024

### 2.1 问题的本质：响应截断（censoring），不是拟合问题

实测反馈（2026-09-23）：部分「颜色×角度」轴在**强度=1 时 GV 已达 240+**。GV 上限 255，
于是默认三档 0 / 512 / 1024 中有两档落在饱和平台区：

| 强度 | 实测 GV（示例） | 对回归的信息量 |
|---|---|---|
| 0 | ~100（暗水平） | 有 |
| 1 | ~242 | 有 |
| 512 | 255 | **零** |
| 1024 | 255 | **零** |

**为什么"全是 255 就没有意义"——三个层面：**

1. **零信息**：饱和平台上的响应方差为 0。回归需要"X 变化 → Y 也变化"的信号；
   平台点没有信号，255 与 255 之间不存在任何梯度。
2. **挤占设计预算**：15 点里约 2/3 的运行被浪费在平台区，真正有响应的窗口
   （0~2）只被 1 个水平覆盖 → 该轴的平方项 β₁₁ **根本无法估计**。
3. **算法无关性**：这是信息论层面的缺失，不是数值问题——再强的拟合器也无法
   从常数里恢复梯度。唯一出路是**在窗口内重新采样**。

结论：0~1024 不是"坚持一下就能用"的默认值，而是必须被标定流程替代的错误假设。

### 2.2 方案：两层机制（预防 + 检测迭代）

**层 1 — 采样前范围标定（pilot scan，预防）**

对每个轴可选执行一次 1-D 快速扫描（其余轴用默认档位直接通过）。

**自适应探测算法（Illinois 修正割线法 + 自动定位，典型 3~7 个读数/轴）**，代替逐级倍增：

1. **暗水平**：测强度 0 一次（该色通道的暗水平，**同色三轴共用**，只测一次）。
2. **探顶**：测强度 1024。
   - GV(1024) < 饱和阈值 → **弱轴**，无饱和，high = 1024，直接跳到第 4 步；
   - GV(1024) ≥ 饱和阈值 → 进入饱和定位。
3. **饱和定位**：在 [已确认安全点, 饱和点] 括号内做**几何中点收缩**（10% 精度即停）。
4. **自动定位（早退规则，操作员零额外操作）**：任何实测点 GV 落在窗口目标 **±10 以内**
   即被自动采用为档位；**上下沿候选都齐 → 立即自动完成并记录**，不再继续探测。
   （档位不要求精确穿越 60/200——落在响应窗口内即有效，两个目标值是约定不是物理量。）
5. **high / low 精调**（仅在早退规则没命中时才走）：在未饱和数据上用
   **割线法（regula falsi + Illinois 阻尼）**预测穿越强度，跳到预测点测量。
6. **人工可改**：建议档位逐轴可编辑；已知窗口的轴（如"1 就 240+"）可直接手填
   `0/1/2` 并跳过扫描；轴全部正常时可整表接受默认档位。

**为什么可以这样省**：普通割线法（regula falsi）在单调凹/凸响应上会单边爬行
（这是它对二分的唯一劣势），Illinois 修正（同一侧连续保留时对保留端点折半阻尼）
恢复超线性收敛；而"±10 GV 直接采用"规则承认了档位只需落在窗口内这一事实。
饱和点（读数被截断）没有斜率信息，只用作括号上界、以几何中点保守收缩。

**实测复现（用户报告的那台机器，0° 红光）**：探测序列
`0 → 1024 → 1 → 32 → 181 → 431 → 65`，**共 7 个读数**自动完成并记录
档位 [65, 248, 431]（实测 GV 60/133/206）；旧"倍增+对分"需 17+ 次且全程手动。

唯一必须人工输入的仍是**每个探测点的 GV 读数本身**（与 AFVI 无软件联机）；
"记录档位/停止探测/推进流程"全部自动。

**层 2 — 采样中饱和监视（检测 → 迭代，向导内闭环）**

- 向导在每点录入后实时检查：**中位数 ≥ 250（阈值可调）或 ≈ 0/暗水平** → 红色告警。
- 告警后提供「重新标定该轴」入口 → 重扫描 → 出新档位 → **该颜色已采运行整色作废**
  → 按新档位重新生成运行单 → 从头重测该色。
- 迭代直到该色 19 点全部无饱和，才进入下一色。

### 2.3 为什么是两层，而不是只做其一

- **只有层 1（先标定）**：标定时刻与正式采样时刻之间若有时移（换班、温升、光源老化），
  窗口可能漂移失效 → 需要层 2 兜底捕获。
- **只有层 2（边采边改）**：没有标定就开采，每个饱和轴都要付出"采到一半才爆炸"的
  重测代价；而扫描一轴只要十几个读数。先标定把大返工概率压到最低。
- 两层共用同一份"档位表"数据结构，实现成本几乎不变。

### 2.4 决策记录（2026-09-23 已确认）

| 决策 | 选择 | 原因（详细） |
|---|---|---|
| 档位粒度 | **每 颜色×角度 独立（9 组）** | 红/绿/蓝是物理上不同的 LED，同角度的不同色 LED 效率差异可以很大（红光灵敏轴可能绿光完全正常）。共享档位会被最差的轴拖累：要么它饱和、要么其他轴被迫压在低分辨率区。独立档位没有额外成本——向导本来就按色分组执行，档位只是数据。 |
| 中途饱和处置 | **整色作废重测** | 编码 c/h 是**按色**的坐标系统。一个色内改档位 = 换坐标系，新旧数据混进同一个回归等于用一套系数拟合两种参数化，数学上不成立。且旧点强度落在新窗口之外，本就是截断废点，重算编码也无意义。整色仅 19 点，重测代价有界；"只补测受影响运行"省下的时间不值得引入混编码的复杂度与出错面。 |
| 目标 GV 窗口 | **60 ~ 200（可改）** | 下沿 60：避开暗水平/环境噪声（<50 区间读数抖动占比大）；上沿 200：避开饱和压平区（>230 后响应变平且轻微漂移就削顶）。中档 ≈130 时上下各有 ~120 counts 的漂移余量。窗口常量放进向导设置，若工艺上有目标 GV 带（如 inspection spec 要求），改成那个值即可。 |
| 等距约束 | **mid = (low+high)/2 强制** | 编码 u=(v−mid)/half 是**线性**映射，只有算术等距三档才能精确对应 −1/0/+1。不等距的三档无法用单个仿射变换映射到设计网格，要么破坏 Plan/02 的全部数学，要么得在原始量纲上拟合（条件数灾难）。所以档位编辑器必须强制中点，只允许动 low/high。 |

### 2.5 退化兜底：窗口只剩两档 → 直接禁用该轴（2026-09-23 实装）

实例（用户报告）：红光 30° `0→0、1→210、2→255` —— 可用强度只有 {0,1} 两个值，
连三个等距档都凑不出来。这种轴**直接禁用**：

- **操作**：标定表中点「禁用」，输入固定值（默认 0 = 该路光不用）。禁用轴不参与
  设计、拟合与调光；采样时该路光保持其固定值不动。
- **设计自动降维**（运行单/拟合/UI 三处同步）：
  | 活跃轴数 k | 设计 | 每色点数 |
  |---|---|---|
  | 3 | BBD 15 | 15+4 验证 = 19 |
  | 2 | 3² 全因子 9 点 + 3 中心（2 因子无角点问题） | 12+4 = 16 |
  | 1 | 6 点 [-1,-1,0,0,+1,+1] | 6+4 = 10 |
  | 0 | 1 点（常数记录，无拟合意义时明确提示） | 1 |
- **为什么降维而不是硬凑**：两档 {0,1} 无法估任何二次项（见 §2.1 零信息论证）；
  而 2 因子 3² 设计保留了交互项 b₁₂，对"该轴已禁用"的现实是数学上最完整的表达。
- **模型的运行假设**：禁用轴固定在选定值——生产现场若动它，预测失效。
  此假设写入模型 JSON（`fixedAxes`）并在 UI/报告中显著标注。
- **优先顺序不变**：先尝试调曝光/增益拉宽窗口（恢复 3 因子）；用户确认该轴
  本来就不该用（如 30° 红光过敏感）才禁用。

## 3. 最少需要多少采样点？

模型：`Y = β₀ + Σβᵢxᵢ + Σβᵢᵢxᵢ² + Σβᵢⱼxᵢxⱼ`（i<j），共 **10 个未知系数**。

| 方案 | 点数 | 说明 |
|---|---|---|
| **数学下限** | **10** | 恰好 10 个方程解 10 个未知数。**不可用**：无自由度、无法评估误差、对噪声零容忍 |
| 中心复合设计 CCD | 17（8 角点 + 6 轴点 + 3 中心） | 需要跑到立方体的角点，极端组合下容易撞上饱和/暗水平（标定后角点已安全，但 BBD 仍更省） |
| **Box-Behnken BBD** | **15（12 边中点 + 3 中心）** | ✅ **推荐**。专为响应面设计，不碰角点，二次项与交互项估计效率高 |
| 全因子 3³ | 27 | 最全面，但工作量翻倍，边际收益低 |
| D-最优设计 | 12 ~ 15 | 点位由算法挑选，适合有"禁区"（某些组合不能打）的情况 |

### 结论：**单色 15 点（BBD）+ 4 个验证点 = 19 次打光。三色按序执行共 57 次打光**（另有可选的范围标定扫描）。

- **12 个边中点**：每次只让两路光取档位极值、第三路居中 → 专门估交互项。
- **3 个中心点**（三轴全取中档）重复 3 次 → 估纯误差、做 lack-of-fit 检验。
- **验证点不参与拟合**：单独记录，用于独立检验预测精度（阶段二的质量门）。
  4 个验证点按**编码**位置 (−½,−½,−½)、(+½,−½,0)、(−½,+½,+½)、(+1,+1,−½) 生成，
  即始终落在**当前档位立方体内部或近边**——档位改了，验证点跟着档位走。
- **窄量程不改变点数**：窗口 0/1/2 与 0/512/1024 在数学上完全等价（编码吸收了缩放），
  BBD 结构、点数、分析流程全部不变。变化只体现在"这三个数是多少"。

> **颜色分组测量策略**：先 Red 连续做完 19 点，再 Green，再 Blue，避免频繁切换颜色。
> **每色开始前**先核对该色三轴档位未变（向导自动比对标定结果）。

## 4. BBD 运行单（编码模式固定，实数值由档位映射）

编码矩阵是 BBD 的本质，**与档位无关**；实数列由"编码 × 档位"动态生成：

| Run | x₁ (0°) | x₂ (30°) | x₃ (60°) | 类型 |
|---|---|---|---|---|
| 1 | −1 (low) | −1 (low) | 0 (mid) | 边中点 |
| 2 | +1 (high) | −1 (low) | 0 (mid) | 边中点 |
| 3 | −1 (low) | +1 (high) | 0 (mid) | 边中点 |
| 4 | +1 (high) | +1 (high) | 0 (mid) | 边中点 |
| 5 | −1 (low) | 0 (mid) | −1 (low) | 边中点 |
| 6 | +1 (high) | 0 (mid) | −1 (low) | 边中点 |
| 7 | −1 (low) | 0 (mid) | +1 (high) | 边中点 |
| 8 | +1 (high) | 0 (mid) | +1 (high) | 边中点 |
| 9 | 0 (mid) | −1 (low) | −1 (low) | 边中点 |
| 10 | 0 (mid) | +1 (high) | −1 (low) | 边中点 |
| 11 | 0 (mid) | −1 (low) | +1 (high) | 边中点 |
| 12 | 0 (mid) | +1 (high) | +1 (high) | 边中点 |
| 13 | 0 (mid) | 0 (mid) | 0 (mid) | 中心点 |
| 14 | 0 (mid) | 0 (mid) | 0 (mid) | 中心点 |
| 15 | 0 (mid) | 0 (mid) | 0 (mid) | 中心点 |

> 表中 low/mid/high **逐轴取自 §2 的标定档位**（9 组独立值），不是全局常数。
> 档位表变更 → 只重算实数列，编码列与运行结构不变。

**运行序必须随机化**（固定 seed 保证可复现、且与向导/Excel 两份载体一致），
并把"运行序"作为独立一列写入 —— 现场按运行序执行，不按行号顺序执行。
理由：光源热漂移、环境光变化都是时间的函数，顺序执行会把漂移混进因子效应里。

## 5. 双载体：采样向导（主）+ Excel 运行单（纸面备份）

### 5.1 交互式向导 `light-sampling-guide.html`（主载体，离线单文件）

三阶段流程：

**阶段 A — 范围标定**
- 逐轴（9 组）决定：跳过（默认档位）/ 扫描 / 手填。
- 扫描界面：提示当前轴的强度值 → 用户录入 GV → 自动推进倍增/对分序列 → 实时画出
  强度-GV 折线与饱和线（GV=250 虚线）→ 结束后给出建议三档（可改，mid 自动锁为算术中点）。
- 档位确认后生成该色运行单。

**阶段 B — 逐色采样（19 点/色）**
- 大字显示当前 run 的三轴设定值 + 3 次 GV 录入 + 实时中位数。
- **饱和监视**：中位数 ≥ 250（阈值可调）→ 红色告警 + 「重新标定该轴」按钮 →
  该色作废、回阶段 A、重生成运行单。
- 进度持久化（localStorage），关闭页面不丢数据；防呆：跳点必须显式确认。

**阶段 C — 导出**
- CSV 首部写入档位元信息（`levels_Red_0deg=0,1,2` 等行），随后是 57 行数据；
  `fit_model.py` 按头部元信息与设计点双重校验档位。

### 5.2 Excel 运行单 `samples.xlsx`（纸面备份/离线录入）

`doe_design.py` 生成，四个 sheet：

#### Sheet `guide`（使用说明）
操作步骤、饱和处置（发现 255 → 停止该色、联系重标定）、读数纪律。

#### Sheet `design`（15 行/色 × 3 色）

| 列 | 名称 | 填写方 | 说明 |
|---|---|---|---|
| A | `run_order` | 脚本 | 1~45 的随机执行顺序（跨色统一） |
| B | `color` | 脚本 | Red / Green / Blue |
| C | `point_id` | 脚本 | 色内 1~15 |
| D | `type` | 脚本 | `edge` / `center` |
| E~G | `x1_c/x2_c/x3_c` | 脚本 | 编码值 −1/0/+1 |
| H~J | `L_0deg/L_30deg/L_60deg` | 脚本 | **按该色档位映射的实数** |
| K~M | `GV_1/2/3` | **人工** | 三次读数 |
| N | `GV_median` | 公式 | `=MEDIAN(K:M)` |
| O | `note` | 人工 | 异常、饱和、作废标记（`作废` = 剔除） |

#### Sheet `verify`（4 行/色 × 3 色）
列结构同上，`point_id` 用 `V1`~`V4`，编码位置固定、实数由档位映射。

#### Sheet `meta`（脚本写、人工复核）

```
machine_id                  : FM1 / FM2 / BM
model_name                  : 例如 6ST2001Q01
levels_Red_0deg             : 0, 1, 2        ← 9 行档位（颜色_角度 = low, mid, high）
levels_Red_30deg            : ...
  …（共 9 行；未标定轴写 0, 512, 1024 并注明 "default"）
saturation_threshold        : 250
gv_window                   : 60, 200        ← 标定用的目标窗口（供复核）
measured_by / measured_at   : 采集人 / 日期
exposure_ms                 : 曝光时间
notes                       : 环境、镜头、温度等
```

> **一机一模型**：`machine_id` + `model_name` + 色 构成模型唯一标识；档位属于
> "机 + 型 + 色语境"的一部分，必须随数据一起记录——**没有档位的 255 不解释为饱和**，
> 没有档位的 GV 数据无法换算回编码，等于废纸。

## 6. 现场采集流程（向导为主，Excel 为备份）

1. **范围标定**：按 §2 完成需要标定的轴，确认 9 组档位（打印档位表留存）。
2. 逐色执行：向导按 run_order 引导，每点设三路光 → **等待稳定（≥1s）** → 读 GV 三次。
3. **饱和即停**：任一点中位数触发饱和告警 → 停止该色 → 重新标定该轴 → 该色重测
   （Excel 用户：在 note 写 `作废`，重新生成运行单后重测整色）。
4. 每完成 5 个点，回中心点（三轴中档）复测一次并记录；相对漂移 > 3% → 暂停检查。
5. 读数纪律：三次取**中位数**；三次极差 > 5 → 标记该点，阶段二单独看残差。
6. 19×3 全部无饱和 → 导出 CSV / 交回 Excel。

## 9. 可选升级路径（当 15 点/色不够时）

若阶段二的 R² < 0.98 或残差呈明显规律，按顺序尝试：

1. 加密到 **CCD 17 点/色**（补 6 个轴点，更好估平方项）。
2. 换 **D-最优 20 点/色**（有硬件禁区时最合适）。
3. 上 **三次项**（系数 10 → 20，采样量至少 20+/色）。
4. 分区间建模（窗口内再切两段，各拟合一个二次面）。

**不要**在没有残差诊断的情况下直接跳"全因子 27 点/色"。
