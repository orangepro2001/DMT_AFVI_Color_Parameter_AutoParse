# AFVI 离线对位（Align）模拟工具 — 技术设计方案 v2

> **v2 变更**：把"模拟 / 练习 / 教学"从附带场景提升为**一等设计目标**，
> 新增「合成数据生成器（Ground Truth）」「管线单步可拆解」「三种使用模式」
> 「练习评分」「失败模式教材」「教室部署」等章节，并据此调整技术栈结论。
>
> 技术栈：Svelte（前端） + Rust（后端） + Tauri（Windows 原生壳）

---

## 0. 需求重定位：这是"教学型工具"，不是"生产型工具"

| 维度 | 生产工具（真机 AFVI） | **本工具（模拟/教学）** |
|---|---|---|
| 目标 | 尽快得到正确结果 | **让人理解"为什么"** |
| 过程 | 黑盒、自动 | **白盒、可单步、可观察中间产物** |
| 正确性 | 结果对不对 | **结果对不对 + 学员学没学会** |
| 关键资产 | 算法 | **带 ground truth 的案例库** |
| 失败 | 尽量避免 | **刻意制造并展示** |
| 环境 | 产线设备 | **教室电脑、离线、可安装** |

**一句话：教学型工具的核心竞争力不是"算得准"，而是"讲得清、出得了题、判得了分、复现得了"。**
这直接决定了下面几个"必须做"的新模块。

## 1. 三种使用模式（同一个内核，三种外壳）

```
┌────────────────────────────────────────────────────────────┐
│                      统一对位内核 (Rust)                     │
│   预处理 → 粗对齐(相位相关) → 精对齐(ECC) → 校验 → 变换输出    │
└───────────┬────────────────┬────────────────┬──────────────┘
            │                │                │
     ┌──────┴─────┐   ┌──────┴──────┐  ┌──────┴───────┐
     │ ① 模拟/仿真 │   │ ② 教学演示   │  │ ③ 练习/考核   │
     │ (生产形态)  │   │ (单步+讲解)  │  │ (出题+评分)   │
     └────────────┘   └─────────────┘  └──────────────┘
```

| 模式 | 面向 | 行为 |
|---|---|---|
| **① 模拟/仿真** | 工程师 / 客户 | 像真机一样一键跑完，给 tx/ty/θ/s + 叠加图 + OK/NG，可对比真机结果 |
| **② 教学演示** | 学员 / 观众 | 单步执行、展示中间产物、配分层讲解、可调参数看效果 |
| **③ 练习/考核** | 学员 | 系统随机出题（已知真值但隐藏），学员手动对位或调参，**自动评分** |

> 三者共用同一个 Rust 内核，只是"外壳"不同：仿真=全自动，演示=可暂停，考核=隐藏真值+打分。

## 2. ★核心新增：合成数据生成器（Ground-Truth Injector）

**这是教学工具区别于生产工具的根本，也是最该优先做的模块。**

没有真值（ground truth），就无法判断"对齐得对不对"，也无法出题和评分。
真机数据是没有真值的（你不知道标准答案），所以必须**自己造**。

```
输入：一张"理想图"（MasterData 渲染图，或一张已对齐的 MedianImage）
参数：tx, ty, θ, scale, 亮度增益/偏移, 噪声σ, 模糊σ, 通道混合, 局部遮挡
种子：seed（保证可复现）

处理：
  ① 取理想图为底
  ② 施加【已知】的几何变换（旋转+平移+尺度）
  ③ 叠加光照变化 / 噪声 / 模糊 / 局部缺陷
  ④ 输出「待对齐图」+ ground_truth.json
```

**产出三元组：`(template, input, truth)`** —— 有了它：

- ✅ **算法自测**：CI 里跑回归测试，误差超阈值即报警
- ✅ **教学演示**：先让学员猜偏移，再一键揭示真值
- ✅ **练习出题**：随机生成 N 道题，系统已知答案
- ✅ **可复现**：同一个 seed → 同一个案例，课堂演示/补考一致

**关键设计：真值可"隐藏/揭示"**，这是出题模式的技术基础。

## 3. ★核心新增：失败模式教材（Error Taxonomy）

教学最怕"只讲成功案例"。要**主动制造并展示失败**，每个都能一键加载：

| 失败模式 | 现象 | 教学点 |
|---|---|---|
| 平移偏移 | 常规场景 | 基础：相位相关原理 |
| 旋转 | 平移法失效 | 为什么需要欧氏/仿射变换 |
| **尺度差** | 纯平移"看起来对"但边缘错位 | **为什么必须做尺度归一化**（呼应 §5） |
| 亮度/对比度差 | 相关峰变弱 | 为什么相位相关对光照不敏感 |
| 噪声 / 模糊 / 失焦 | 峰值旁瓣比(PSR)下降 | 如何用置信度判定 |
| **周期性结构（BGA 阵列）** | 相位相关出现**多个峰 / 错峰** | **经典坑：阵列导致歧义对齐** |
| 部分遮挡 / 坏板 | 局部区域失效 | 为什么需要分块 Local Align |
| 通道选错 | 基准点不可见 | 通道选择的重要性（Light×RGB） |

> BGA 阵列的"多峰歧义"是最有教学价值的一课——**BGA 板天然就是周期性图案**，正好对应实机图里的 pad 矩阵。

## 4. ★核心新增：管线单步可拆解（白盒化）

生产管线是"一条龙"，教学管线必须**每一步都能停下来看**：

```
步骤条：[预处理] → [粗对齐] → [精对齐] → [校验] → [补偿]
            ▲
        点任意一步 → 显示该步的：输入图 / 输出图 / 中间产物 / 数值
```

每个 stage 输出"中间产物"：
- 预处理：灰度图、CLAHE 后、金字塔各层、掩膜
- 粗对齐：**频谱图、互功率谱、峰值位置、PSR**
- 精对齐：迭代次数、相关系数曲线、warp 后的图
- 校验：各基准点的 NCC 得分、距离一致性
- 补偿：红绿叠加图、差异图

**这不是调试功能，是教学内容本身。**

## 5. 问题建模（技术核心不变）

| 项 | 说明 |
|---|---|
| 参考图 (Template) | MasterData —— Gerber/ODB 渲染的"金图"，无噪声、理想几何 |
| 待配准图 (Input) | MedianImage —— 已初步对齐的实拍合成图 |
| 待求变换 | 至少 (tx,ty)；建议相似变换 (tx,ty,θ,s) |
| 输出 | 变换矩阵 → 重投影区域网格/ROI → 叠加图与差异图 |
| 真正的难点 | **不是翘曲**（Pixel 已解决），而是**"合成图↔实拍图"的域差**与**尺度/坐标系差异** |

### 5.1 最重要的判断：能靠数据准备解决的，不要交给算法

MasterData 与 MedianImage 的 mm/pixel 很可能不同。**先按物理单位归一化尺度与坐标系，再上算法。**

从 Gerber 拿真实 mm、从 MedianImage 拿扫描 µm/pixel，生成 MasterData 时**按 MedianImage 的像素网格重采样**。
这样问题退化成"纯平移 + 极小残差"，难度和失败率大幅下降。

> 教学价值：这也正好是 §3 里"尺度差"那一课的反面教材——**先归一化，就不需要算法去猜尺度。**

## 6. 算法分层（按难度取舍）

| 层级 | 算法 | 自由度 | 原理一句话 | 难度 | 鲁棒性 | 精度 | 建议 |
|---|---|---|---|---|---|---|---|
| L0 | 投影/质心法 | tx,ty | 二值化后行/列投影峰值 | ★ | 低 | 像素级 | 兜底粗定位 |
| **L1** | **相位相关** | tx,ty | FFT 互功率谱逆变换峰值 = 位移 | ★★ | **高** | **亚像素** | **首选粗对齐** |
| **L2** | **模板匹配 NCC** | tx,ty | 归一化互相关滑窗取峰 | ★★ | 中 | 亚像素 | **基准点(MK)精修/校验** |
| L3 | ORB/SIFT + RANSAC | 相似/仿射/单应 | 关键点匹配求变换 | ★★★ | 中 | 高 | 有真实旋转/尺度才用 |
| **L4** | **ECC** | 平移/欧氏/仿射 | 迭代 warp 最大化相关系数 | ★★★ | 高 | **亚像素** | **首选精对齐** |
| L5 | 深度学习 (SuperPoint/LoFTR) | 任意 | 学习式特征 | ★★★★★ | 最高 | 高 | 最后兜底 |

**为什么首选"相位相关 + ECC"而不是 SIFT/ORB？**

- **相位相关**只用频域相位（幅度归一化），**对光照/亮度不敏感**，不需丰富纹理，天然亚像素。对"合成↔实拍"域差大的场景，比特征点稳。
- **SIFT/ORB 的风险**：渲染图与实拍图的纹理、边缘锐度、噪声分布差异大，关键点可能匹配错；且只需平移，用单应（6/8 自由度）反而易被外点带偏。
- **ECC**：成熟实现，配合相位相关初值稳定收敛到亚像素。

> **教学价值**：L0→L5 正好是一条完整的"由简到繁"教学主线，可逐层演示"什么时候简单方法就够、什么时候必须上重武器"。

## 7. 推荐管线（Coarse-to-Fine）

```
[输入] MasterData(已归一化尺度) + MedianImage
   │
   ├─ 0. 预处理  选通道 → 灰度+光照归一化(CLAHE) → 金字塔 → 有效区域掩膜
   ├─ 1. 粗对齐  最粗层【相位相关】→ 全局 (tx,ty) 亚像素
   ├─ 2. 精对齐  以①为初值【ECC 欧氏/仿射】→ 亚像素 (tx,ty,θ[,s])
   ├─ 3. 校验    对 MK（方形pad/倒三角/十字）做【NCC】交叉验证
   ├─ 4. 补偿    变换矩阵重投影 ROI/区域网格 → 对齐叠加图
   └─ 5. 判定    PSR / NCC / 残差RMS / 基准点距离一致性 → OK / 人工 / NG
```

**分层对齐对应实机两级**：Global（整条 Strip 相似变换）+ Local/per-block（每个 CELL 微调，吸收残留误差）。

> 每个箭头在"教学演示模式"下都是一个**可暂停的步骤**（见 §4）。

## 8. 技术栈选型（教学场景下的重新权衡）

| 方案 | 能拿到什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. `opencv` crate** | phaseCorrelate / findTransformECC / matchTemplate / ORB / RANSAC | 业界参考实现，开发最快 | Windows 需 OpenCV + LLVM/Clang，构建是真痛点；**源码不可读，教学价值低** |
| **B. 纯 Rust** `image`+`imageproc`+`rustfft`+`nalgebra` | NCC 有现成；相位相关/亚像素需自写（~150行） | **零依赖、体积小、迭代快、源码可读可单步** | 无 ECC/特征匹配成熟实现 |
| **C. 混合（推荐）** | 纯 Rust 落地 L1+L2，算法封在 `trait Aligner` 后留替换口；需要时再挂 opencv / kornia-rs | 兼顾构建速度与可扩展 | —— |

### ★教学场景让"纯 Rust"的优势被放大
1. **源码可读、可单步调试** → 学员能真正看懂算法，而不是调一个黑盒 API。
2. **教室电脑零依赖** → 只需 Rust 工具链即可构建，不必装 OpenCV+LLVM（这正是教学环境最常见的卡点）。
3. **可复现** → 同一份代码、同一个 seed，人人结果一致。
4. **可对照** → 可另做一个"OpenCV 参考实现"作对照演示，说明"工业界怎么做"，但主线仍是可读的纯 Rust。

> **结论强化**：面向教学，**优先纯 Rust**；OpenCV 作为"对照组/兜底"，而非主线。

## 9. 架构（Tauri + Svelte）

194 MP（16384×11840）单通道约 580 MB，**绝不能整图塞进前端或一次性 IPC 传字节**。

```
┌──────────────────────── Svelte 前端 ─────────────────────────┐
│ · 分块金字塔查看器（deep-zoom，按需请求瓦片）                 │
│ · 【教学】步骤条 + 中间产物面板 + 分层讲解 + 参数实时反馈      │
│ · 【练习】题目区 + 手动对位画布 + 提交评分                     │
│ · 画 ROI/基准点、拖拽微调、叠加模式（红绿/差异/闪烁）          │
└───────────────────────────┬──────────────────────────────────┘
                            │ Tauri IPC（传路径/瓦片请求，不传大 buffer）
┌───────────────────────────┴──────────────────────────────────┐
│                        Rust 后端                              │
│ · 图像 I/O；Gerber/ODB → MasterData 渲染                      │
│ · ★ 合成数据生成器（Ground-Truth Injector）                    │
│ · ★ 可分解对位管线（每 stage 输出中间产物）                    │
│ · 金字塔 & 瓦片生成 + 磁盘缓存                                │
│ · rayon 多线程 + Tauri event 上报进度                         │
│ · ★ 案例库 / 评分器 / 参数持久化                              │
└──────────────────────────────────────────────────────────────┘
```

要点：
- **瓦片协议**：Tauri 自定义协议 / `ipc::Response` 返回二进制瓦片，前端 `<canvas>` 拼装。
- **对齐只在降采样层算**，全分辨率仅用于可视化与 ROI 精修。
- **教学数据集可降采样**：教室用几个 2048×2048 的 FOV 单元即可，不必上 194 MP（见 §12）。
- **确定性**：所有随机（噪声、出题）走 seeded RNG。

## 10. ★核心新增：练习 / 考核子系统

```
出题：生成器随机 seed → (template, input, truth[隐藏])
   │
   ├─ 学员作答方式（可选）：
   │    · 手动对位：拖拽叠加图直到"对齐"（复刻真机"画定位点"的操作）
   │    · 参数调优：选通道/金字塔层/算法，观察结果
   │    · 完整流程：从预处理到校验走一遍
   │
   └─ 评分：误差 = ||求解变换 − 真值||
        · 平移误差 (px)  · 角度误差 (deg)  · 尺度误差 (%)
        → 优秀 / 合格 / NG 三档
        · 手动模式：实时显示残差曲线，提交后与真值对比
```

**教学闭环**：`出题 → 学员操作 → 即时反馈 → 揭示真值 → 复盘`。

> 手动对位模式尤其贴合实机——**真机就是"画几个定位点然后尽量对齐"**，学员先体验一遍，再学算法，理解会深得多。

## 11. ★核心新增：教学演示 UI 要点

- **分层讲解**（同一操作，三档文字）：
  - 🟢 直觉层（给操作员）："我们在找两张图最像的位置"
  - 🟡 数学层（给工程师）：互功率谱、相位、峰值拟合
  - 🔴 代码层（给开发者）：对应 Rust 函数与源码行

- **叠加模式 5 种**：并排 / 50%混合 / 差异 / 闪烁 / **红绿立体（Master=红，Median=绿，对齐好=黄灰）**——红绿立体最直观。
- **失败案例一键加载**：对应 §3 的 taxonomy。
- **导出案例包**：把当前 (template, input, truth, 参数) 打包，发给学员复现。

## 13. 工程细节（决定成败）

1. **通道选择**：自动评估每个通道（Light×RGB）梯度能量，选基准点对比度最高者，允许手动覆盖——对齐实机习惯。
2. **亚像素**：相位相关峰值邻域抛物线插值（~0.1 px）；ECC 原生亚像素。
3. **校验别只看一个数**：
   - NCC 峰值 → 单点可信度
   - **PSR（峰值旁瓣比）** → 全局对齐是否唯一可信（**周期性 BGA 案例的关键指标**）
   - 残差 RMS → 整体质量
   - **基准点距离一致性 → 能抓出尺度错误（纯平移法抓不到）**
4. **失败兜底**：结果带置信度，低置信度提示人工；提供手动微调后重新锁定。

## 15. 参考代码骨架（纯 Rust 路线）

### 15.1 相位相关（FFT 求平移 + 亚像素）
```rust
use rustfft::{FftPlanner, num_complex::Complex};

/// 返回 (dx, dy) 亚像素平移，使 input ≈ shift(template, dx, dy)
fn phase_correlate(a: &[f32], b: &[f32], w: usize, h: usize) -> (f64, f64) {
    let mut planner = FftPlanner::new();
    let fft = planner.plan_fft_forward(w * h);
    let ifft = planner.plan_fft_inverse(w * h);

    let mut fa: Vec<Complex<f32>> = a.iter().map(|&v| Complex::new(v, 0.0)).collect();
    let mut fb: Vec<Complex<f32>> = b.iter().map(|&v| Complex::new(v, 0.0)).collect();
    fft.process(&mut fa);
    fft.process(&mut fb);

    // 互功率谱（幅度归一化 => 对光照不敏感）
    let mut cross: Vec<Complex<f32>> = fa.iter().zip(&fb)
        .map(|(x, y)| { let c = x * y.conj(); let m = c.norm().max(1e-12); c / m })
        .collect();
    ifft.process(&mut cross);

    let (mut bx, mut by, mut best) = (0usize, 0usize, f32::MIN);
    for y in 0..h { for x in 0..w {
        let v = cross[y * w + x].re;
        if v > best { best = v; bx = x; by = y; }
    }}
    // 抛物线插值做亚像素
    let sub = |c: f32, l: f32, r: f32| 0.5 * (l - r) / (l - 2.0 * c + r + 1e-12);
    let cx = |x: usize| cross[by * w + x].re;
    let cy = |y: usize| cross[y * w + bx].re;
    let sx = sub(cx(bx), cx((bx + w - 1) % w), cx((bx + 1) % w)) as f64;
    let sy = sub(cy(by), cy((by + h - 1) % h), cy((by + 1) % h)) as f64;

    let mut dx = bx as f64 + sx;
    let mut dy = by as f64 + sy;
    if dx > w as f64 / 2.0 { dx -= w as f64; }
    if dy > h as f64 / 2.0 { dy -= h as f64; }
    (dx, dy)
}
```
