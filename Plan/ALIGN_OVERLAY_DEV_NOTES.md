## 1. 目标与真机效果定义

真机 Pixel Vision 的 TEACH → Align/ROI → Metal 视图：**绿色阻焊板面 + 黑色走线/焊盘 + 黄色露铜标记**（基准点十字、pad、BGA 区细走线）。两套图层来自真机自己的成套理想渲染数据，因此几乎完美重叠。

我们的数据里没有这套成套渲染，只有两张二值掩码 tif。目标：用这两张掩码**合成**出同等的显示效果，供 ALIGN 工具的 Align/ROI 显示用。

**用途分层（用户拍板）**：
- 彩色合成图 → 仅用于**显示**（Align/ROI 观感）；
- 原始真实掩码 → 仅在主画面**真正与 MedianImage 做对齐时**使用（M2+ 的对位管线），不得被显示用的二次处理污染。

## 3. 图层语义：从猜错到实证

**过程**（教训：不要凭截图猜极性）：
1. 最初凭用户两张截图假设：稀疏标记图 = UNIT_0、板面图 = Pattern。
2. 用该假设合成 → 满屏黄色（绿层完全被盖住）→ 明显不对。
3. 写 `examples/inspect_masks.rs` 输出**灰阶直方图**：UNIT_0 白 64%、Pattern 白 2.7% → 二值掩码、极性如上表 → **角色与假设相反**。
4. 用直方图定正后一次合成成功。

**结论**：`GB\Pattern.tif` 是金属标记层（黄），`L01\UNIT_0.tif` 是板面层（绿）。"GB" 应为 Gerber marks 层、"L01" 为板面/阻焊层，命名与直觉相反，**以直方图实证为准**。

## 4. 合成方法（已验证）

黑色画布（5860×4020 原生 → 工作宽 1400 下采样，Triangle 滤镜）：
1. UNIT_0 白像素 → 绿 `rgb(26,158,40)`；黑（走线/焊盘/孔）保持黑——与真机深色线路一致；
2. Pattern 白像素 → 黄 `rgb(255,214,0)`，盖在绿上（金属优先）；
3. 输出 JPEG 走既有预览通道（集成时）。

两掩码均 luma8 直读（`image` crate，0.25，需 `png`/`tiff` feature）；直方图检查确认无中间灰阶（纯二值，阈值 128 无损分割）。

## 5. 配准（对齐两层的关键，走了五步弯路）

### 5.1 为什么需要配准
- 两层**物理比例不同**：UNIT_0 是整机视野渲染（板占中带 ~55%），Pattern 是紧凑 Gerber 渲染（板占 ~92%）（截图阶段结论；真实 tif 同为 5860×4020，但内容框架仍不同）。
- 两层内容存在**真实 ~25px（原生尺度）互偏**——不是同一网格的完全重合渲染。
- 用户实测真机"几乎完美重叠"指的是真机自己的成套渲染；我们的两层必须配准。

### 5.2 最终方案（锚 = 机器自己的基准点十字）
1. `bbox_crop`：掩码裁剪到白像素包围盒（四角基准十字是全局极值，天然消除未知边距）。
2. 统一到工作宽 1400（Triangle）。
3. `cross_anchor`：在四角 18% 窗口内找第一个白像素，**无界洪泛**该 4-连通组件（20 万像素熔断保护），取**组件包围盒中心**为锚。
4. `fiducial_transform`：scale = |sr_BR−sr_TL| / |m_BR−m_TL|（两角中心距比）；平移 = TL/BR 两角各自解出的平移**取平均**（SR 十字贴边被截导致的内偏，TL 与 BR 方向相反，平均后一阶抵消）。
5. 平移精修：几何 seed 附近 **±5px、以基准点窗口 Dice 为目标**的小搜索（只动平移，不动 scale）。

### 5.3 弯路与教训（每条都真实付出过迭代）
| # | 弯路 | 症状 | 根因 | 解法 |
|---|---|---|---|---|
| 1 | 手工裁剪常数估计截图 UI 边距 | 包围盒尺寸超过裁剪后画布 | 实际 PNG 分辨率与渲染显示尺寸不一致；底部状态栏**白字**留在掩码里污染 bbox | 先落盘二值掩码目检，再定精确裁剪（右 131 / 下 50px）；教训：**UI 截图当数据源必须先可视化掩码** |
| 2 | 窗口受限洪泛取**质心** | 十字视觉偏移 ~4px，配准怎么调都歪 | 基准十字长臂伸出 18% 窗口被截断，质心偏向窗口内 | 改**无界洪泛 + 包围盒中心** |
| 3 | 全图 IoU 精修平移（±8px） | 十字中心漂移、膨胀被迫加大去"补洞" | 稀疏金属掩码的全图 IoU 噪声极大，2px 的错位在分数上不可见 | 精修范围收到 ±5px，目标改基准点窗口 Dice |
| 4 | 以全图 IoU 选膨胀量 | 扫描永远选上限（越胖分越高），BGA 细走线糊成一片 | IoU 只奖励"黄盖绿"，不惩罚过胖 | Dice（对过胖/过瘦对称惩罚）+ 最终膨胀量手动定（见 §6） |
| 5 | 闭运算 r2 平"歪歪扭扭" | BGA 细走线间隙（3-5px）被焊死成色块 | 闭运算半径 ≥ 间隙一半必然粘连 | **放弃闭运算**；毛边在工作分辨率下不可见，细走线完整性好得多 |
| 6 | 认为配准后十字应等大重合 | 角落 4x 放大始终"不重合" | **两层基准标记本来就是不同设计**：金属标记 = 小对称十字（臂展 50），SR 开窗 = 长不对称十字（臂展 81，竖臂偏心）——"完美重叠"在数据上不存在，真机重叠的是它自己的成套渲染 | 接受"同心 + 环差"，交付判据改为：同心（±2px）+ 标记饱满 + 细走线完整 |

**核心教训**：配准/评分目标必须与"对应的确定性"绑定——只有基准十字是确定对应，其余 2.7% 白像素的对应关系未知，任何把它们算进目标函数的全局指标都会被噪声主导。目检（放大对比图）是最终判据，数值分数只做排序。

## 6. 理想化（"二次处理"）最终参数与理由

**最终采用：纯膨胀 1px（工作网格；≈4px 原生），无闭运算。**

理由链（全部实测）：
- 闭运算 r1/r2：r2 直接焊死 BGA 细走线；r1 也会闭掉 2-3px 间隙 → 剔除；
- 膨胀 4-6px：基准十字变胖至覆盖绿开窗（IoU/Dice 分数更高但目检是" Blob"）→ 剔除；
- 膨胀 1px：标记稍饱满（补偿部分蚀刻收缩）、间隙全保、1x 缩放下毛边不可见 → 采用；
- 参数是**显示偏好**而非物理量：集成时应做成可配置（见 §8）。

产物对照（本轮验证证据，均在 `Plan/` 下）：
- `align_overlay_demo.png`：最终合成全图（理想化后）；
- `debug_corner_before.png` / `debug_corner_after.png`：角基准十字 4x 前/后；
- `debug_zoom_before.png` / `debug_zoom_after.png`：BGA 区 2x 前/后；
- `debug_sr_corner.png` / `debug_metal_corner.png`：两层角部分离图（配准测量用）；
- `debug_real_UNIT_0.png` / `debug_real_Pattern.png`：真实 tif 缩览（极性实证）。

## 10. 备选思路评估：在绿层上"寻找 Pattern 涂黄"（2026-10-04，用户提出）

**思路**：不做全局变换后盖章，而是在 UNIT_0（绿层）上搜索 Pattern 特征的位置，就地涂黄。

**两种读法与结论**：

| 读法 | 做法 | 能修 | 硬伤 |
|---|---|---|---|
| A. Pattern 当模板做匹配 | 逐特征 NCC 定位后，涂 Pattern 自己的形状 | 每处标记的局部残差（全局变换只有一套 scale/tx/ty，板上不同位置有 ±2px 级残余） | 修不了"偏小/歪扭"（形状还是 Pattern 的）；BGA 区 Pattern 白走线落在 UNIT_0 黑 pad 上，局部对比度语义不同，NCC 失明 |
| B. Pattern 只做"指认"，涂绿层几何 | 找到对应位置后把绿层形状涂黄 | 形状大小绝对一致（字面"完美重叠"） | BGA 走线在绿层是黑 pad、无对应白几何，按规则会消失（需再打补丁）；基准点绿环（阻焊 dam）被整片涂黄，丢真机层次 |

**判定**：
- 作为**显示层**二次处理：不采纳。dilate 1px 方案在 1x 缩放（实际使用视角）下已等效真机观感；读法 A/B 需引入组件标记 + 逐特征匹配 + 融合规则三层新复杂度，改善只在 4x 放大下可见，且各有特征丢失风险。
- 作为**对位管线**思路：成立且重要——"在参考图上寻找 Pattern"就是 Align 的核心动作。归档为 **M5 基准点 NCC 定位**的实现思路（`imageproc::template_matching::match_template` + 基准窗局部搜索骨架本轮已写好），也是叠加图与 MedianImage 真实验对齐（M2+）的机制原型。

**结论**：显示层维持"配准 + dilate 1px"；本思路转入 M5 思路库存档。

## 11. CV 强化路线："让算法真正理解在哪里"（2026-10-04，用户追问）

**问题**：能否不依赖坐标和对齐，让算法真正理解"这里对应的是哪个位置"？

**原理性回答**：CV 里所有"理解对应"的方法本质都是 **matching（找对应）+ transform（拟合变换）** 两步，区别只在匹配的表示层级——像素级（光流/相位相关）、特征级（SIFT/ORB/SuperPoint+SuperGlue）、形状级（Chamfer/距离变换）、语义级（LoFTR/DINO 对应）。"不依赖坐标"严格说不存在：它们不依赖人工给的坐标，但输出仍是坐标（对应点对/变换参数）。

**本数据的物理边界（关键）**：Pattern 与 UNIT_0 不是同一场景的两张照片，而是不同设计层的渲染——金属基准点=小对称十字 vs 阻焊开窗=长不对称十字；BGA 区白走线 vs 黑 pad（极性相反）。**真对应只存在于"标记中心"这一层级**，像素级/形状级对应在设计上不成立。因此"检测特征（十字锚）→ 中心级对应 → 相似变换"已经是这份数据上正确的理解粒度；当前的朴素方案方向没有错。

**可强化的层级（按性价比）**：
1. **Chamfer/距离变换匹配（形状级，推荐）**：对 SR 层做距离变换（`imageproc::distance_transform` 现成），金属掩码白像素"吸"最近绿层边界，以总距离为目标做局部搜索或逐组件定位——不需要点的标签，对形状差异鲁棒，可把全局 ±2px 残差压到逐特征归位。适合作为集成时 `align_load_overlay` 配准的增强项。
2. **多对应点 + RANSAC（工程加固）**：锚从 2 个十字扩展到 4 角 + 高置信 pad 中心，RANSAC 剔坏对应。属 M5 范畴。
3. **深度学习语义对应（LoFTR/SuperPoint+SuperGlue）**：技术上存在且正是干这个的，但 (a) 吃照片纹理，二值 Gerber 掩码低纹理，预训练权重大概率水土不服、需自造数据训练；(b) 模型权重违背 D1 纯 Rust 离线约束。计划已预判——P5 backlog（SuperPoint/LoFTR，不排期）维持不变。

**落点**：
- 显示层维持现状（Chamfer 精修在 1x 使用视角无可见收益）；
- "理解在哪里"的主战场是**对位管线**：MedianImage 是真实相机图（有纹理、有形变），对它"寻找 Pattern"= M2 相位相关全局粗对齐 → M5 NCC 基准点定位 + RANSAC 的完整链条，本笔记 §10 的思路在那一侧全部成立。

**性能修复（首次加载慢，2026-10-04 当天）**：首版把合成放进了 `MEDIAN_DECODE_GATE`——选模型瞬间 4 个加载（两侧 MEDIAN + 两侧 overlay）全串行，overlay 排在两个大条图解码后面；且两侧 overlay 都预加载，BM 侧 23.6MB 抢带宽。修复：①overlay 解码**移出大图闸**（层缓冲仅 ~24MB luma，非 gigapixel，并发两份 ~50MB 无压力，gate 的存在意义是限制 gigapixel 缓冲）；②**只预加载当前激活侧**，切侧时按需加载（`loadPattern` 有序号守卫，重复触发无害）。首次加载从"排队等两个大条图+双份下载"降到"单份 24MB 共享读取 + ~2s 管线"。

**后续调参入口**：理想化膨胀（`IDEALIZE_DILATE_PX`）、工作分辨率（`WORK_WIDTH`，当前 4096，若缩放观感偏软可升 2048 并同步复查膨胀量）、颜色常量（`SR_GREEN`/`METAL_YELLOW`）。

## 8.2 边缘/大小/放大失真修复（2026-10-04 第二轮，用户实测反馈）

用户放大实测反馈两个问题：①黄色走线相对黑 pad **边缘不对齐、大小不对**（ traces 偏肥、边缘切过 pad 边界）；②**放大后失真**（马赛克感）。

**根因 1（大小不对，真 bug）**：配准前每层各自 `bbox_crop → 缩放到同一宽度`——但两层的白像素包围盒含的边距不同（SR 十字贴角 vs 金属层含右缘极值标记），导致**两层被施加不同缩放系数**（25fbo015-15 上实测 1.111 vs 1.176，差 6%）。配准解出的 scale=0.9447 正是该误差的直接证据。**修复：两层共用同一缩放系数**（master = work_width / sr_bbox_width），相对几何严格保持。
**根因 2（放大失真）**：工作分辨率 1400px，前端放大 3-4x 时等效 4-8 倍上采样。**修复：`WORK_WIDTH` 1400 → 4096**（与 MEDIAN 预览上限同级，放大观感与条图一致；4096×2810 RGBA ≈ 46MB 内存无压力）。
**配套**：所有标定参数改为**按分辨率比例化**（基准网格 1400：`FIDUCIAL_WIN=160` → `width×160/1400`；精修 ±5px → 同比）；`compose_overlay_with(sr, metal, work_width, dilate_px)` 参数化供重标定，`compose_overlay` 为 app 默认入口。
**退化守卫（测试揪出的生产 bug）**：两层锚点退化成同一点时（如金属层无基准十字、仅一块孤立 pad 被洪泛两次），scale = dist/0 = ∞，`CachedMask::scaled` 试图分配 **12TB** 内存直接 abort。已加守卫：锚点间距 < 25% 短边或 scale ∉ [0.25,4] → 返回 Err（走灰图回退）。

**重标定结果（真实 tif，4096 网格）**：膨胀 1px@4096 ≈ 0.35px@1400 旧粒度，细走线根根分明、间隙完整、圆环干净——边缘与大小问题随共享缩放+细粒度一并解决。产物：`Plan/align_overlay_demo_d{0,1,2}.png`（全图三档）+ `debug_zoom_d{0,1,2}.png`（BGA 区 2x）+ `debug_corner_d1.png`（角十字 2x）；`align_overlay_demo.png` = d1（默认档）。已知边界（不变）：两 层基准十字是不同设计，角十字在 2x 下仍有 ~30px@4096（<1% 板宽，1x 不可见）的视在偏移——Dice 按面积最优对位，非人眼居中；彻底解决属 M2/M5 对位管线。

**代价**：4096 管线 debug 模式下较慢（单测 ~50s，release 亚秒级）；测试套件中全分辨率用例已按比例化小网格覆盖，另保留一个 4096 端到端用例。

## 8.3 语义修正 + 板中心精修（2026-10-04 第三轮，用户实机对照反馈）

用户出示同模型实机 Metal 视图并纠正语义：**黄标应落在绿层的对应部分里；黑的地方是 Open 区域**（实机截图中 BGA 带两端的黑矩形内没有任何黄色）。此前我们"金属层全部涂黄"的做法把走线涂到了 Open 黑区上——错。

**修正 1（渲染语义）**：`render_composite` 改为 **黄 = Pattern白 ∧ SR白**——黄色严格限制在绿层白色对应部分内，Open 黑区永不涂黄，边缘自动跟随绿层几何（这同时就是"边缘对齐"的答案：黄边=绿层白区边界，物理上不可能切出界）。

**修正 2（板中心错位，根因实锤）**：用户语义修正后暴露了真正的对齐问题——修正 1 之后 BGA 带的黄色若仍落在黑 pad 上会直接消失，实测发现走线确实错开了约半个线距。根因：**角十字是不对称设计，bbox 中心带固有偏置 → 全局 scale 微差 → 误差随离锚点距离线性放大**（角上 0px、板中心 ~40px 原生 ≈ 半个线距）。**修复：`refine_board` 全板 Dice 精修**——基准 seed 后在 1024px 代理网格上扫 5 档 scale（±1%）× ±15px 平移，再全分辨率 ±px 收敛；共享缩放修复后 BGA 细走线的高频结构给出尖锐且诚实的峰值（此前的"游走"发生在每层各自缩放失真的病态地形上）。真实数据实测：配准从 scale 0.9835/(12,9) 精修到 0.9932/(14,10)，走线落回白线。

**测试夹具教训**：合成图的层间偏移必须**整体刚性平移**——最初只给十字加了偏移、pad/条纹没加（物理上不存在的"非刚性层"），导致 Dice 在错误的偏移处取优、测试假失败。修夹具后 32 测全绿（4096 端到端用例标注 `#[ignore]`：debug 跑全分辨率管线 ~50s，真实数据由 example 覆盖）。

**产物更新**：`Plan/align_overlay_demo_d{0,1,2}.png`（语义修正后重渲染）、`debug_zoom_d1.png`（BGA 区：细走线 + 绿间隙 + 端部黑 Open，与实机一致）、`align_overlay_demo.png` = d1 默认档。**遗留边界**：两层基准十字设计不同（标记 vs 开窗）+ 黑间隙 vs 绿间隙是 L01 数据源与真机 SR 渲染的差别，属数据层面，非算法可修。

## 8.4 横向尺寸补偿（2026-10-04 第四轮，用户实机对照："横向太短"）

同区域放大对比实机：位置全对，但**黄色金属标记横向偏窄**（小 pad 呈瘦长条，实机是宽矩形；BGA 走线也偏细）。这是 GB 层的蚀刻后横向收缩 vs 实机标称渲染的差别——且**横向纵向不对称**（y 向此前已匹配）。

**修正**：理想化从各向同性膨胀改为**各向异性**——`idealize(metal, dilate_x, dilate_y)`，自写可分离 1-D 最大值滤波（imageproc 只有各向同性形态学）。在真实数据上标定 dx∈{2,4,6}（dy=1）：dx6 右半带焊死（线距 3-5px 承受不住）、dx2 仍偏瘦、**dx4 与实机一致**（黄条宽、绿缝细）——定为默认 `IDEALIZE_DILATE_X_PX=4, IDEALIZE_DILATE_Y_PX=1`。

**产物**：`Plan/align_overlay_demo_dx{2,4,6}.png` 三档 + `debug_zoom_dx{2,4,6}.png`（BGA 2x）+ `debug_corner_dx4.png`（角十字）；`align_overlay_demo.png` = dx4。调参入口即两个常量。

**注意**：该补偿按模型校准（25fbo015-15）；不同机型 GB 层的收缩比例若不同，可能需要按模型自适应（未来可从黑 pad 与黄条的实测宽度差自动推算 dx——记入 M5 思路）。

## 8.5 架构修正：统一坐标系 + 多区域局部配准 + 验收门（2026-10-04 第五轮）

用户反馈"不同的区域需要的增益好像不一样，需要更细致高级的算法处理"。实施三层升级：

**①统一坐标系（架构级真 bug）**：此前两层各自 `bbox_crop` 后被当作同一坐标系使用——实际上 SR 裁剪原点 (9,8)、金属裁剪原点 (11,12)（合成）/各不相同的原生原点（真实），锚点数学、平移、渲染全部在混用两个帧。修复：两层裁剪到**联合白色包围盒**（union bbox）并用同一缩放系数，全程单一坐标系。合成测试（offset (0,0) 时锚点差应为 0）立即可复现旧代码的帧混用误差。

**②多区域局部配准 `refine_local`**：3×3 探测 tile（每个 1/8 画布半宽）各自在 ±12px（1400 基准）范围内做 Dice 局部搜索（1/4 分辨率粗搜 + 全分辨率 ±3 收敛），≥0.05 分的 tile 投票；逐轴最小二乘拟合 `offset = k·(位置−中心) + t`（k 即残余 scale 误差），一次 2.5×中位数离群剔除。**验收门**：候选必须使**全板 Dice** 严格优于基准点配准（+0.005）才采纳，否则保留——tile 投票在周期性 BGA 带上会锁错线距倍数（实测投出 (21,−35) 的野值，全板分数更差被门拒绝），不能盲信。

**③各向异性膨胀**（§8.4 的正式化）：`idealize(metal, dilate_x, dilate_y)`，自写可分离 1-D 最大值滤波（imageproc 仅各向同性），标定 dx=4/dy=1。

**实测（25fbo015-15）**：refine_local 的 3 个有效投票被验收门正确拒绝（全板 Dice 0.0476 < 0.0501——该模型的层间残差以横向蚀刻收缩为主，基准点配准已是最优，各向异性膨胀负责补偿）；合成测试验证了投票-拟合-验收链路在可判别夹具上正常工作。产物更新为 `align_overlay_demo_dx{2,4,6}.png`。

**遗留**：若未来遇到层间存在真实局部形变（非刚体）的模型，refine_local 的逐 tile 偏移可扩展为分片仿射（mesh warp）——骨架已就位。

## 12. M1 合成数据生成器（2026-10-05，`align::generator`）

Plan 05 M1 落地记录。教学三元组 `(template, input, truth)` 的生成契约，M2 相位相关的输入即由它提供。

**RNG（自写，不引 rand crate）**：splitmix64 展开 256-bit 种子 → xoshiro256** → Box-Muller 高斯（成对产出缓存）。理由：字节级复现是 D4 契约，三方 RNG crate 升级换流会静默毁掉整个案例库；自写 ~40 行且是 M4 教学素材。已知边界：`ln/sin/cos` 走平台 libm，字节同一性按"同一 Windows x64 构建"承诺，不承诺跨架构。

**Warp（手写逆映射 + 双线性）**：前向 `q = c + R(θ)·(s·(p−c)) + t`（c=工作网格中心），逐输出像素逆解采样，出界填黑。不用 imageproc `Projection`：语义易混（正逆映射文档陷阱）、且自写版可读可教学。边界内容旋转出画布被裁——两侧画布同尺寸正是 M2 相位相关需要的。

**退化链（顺序即契约，模块文档写死）**：光照(gain/offset) → 高斯模糊(imageproc) → 噪声 → 遮挡（RNG 定位的黑矩形）。真值派生（若未指定）在退化流之前抽样——指定真值不会扰动噪声流，"指定 vs 派生"同一 seed 退化一致（有单测锁住）。

**案例库**：`<app_data>/align-cases/<模型_侧_seed>/{case.json, template.png, input.png}`。PNG 不用 JPEG（保字节复现）；case_id 撞名 = 幂等重生成（课堂可随时重推案例）；list 对损坏文件夹 stderr 跳过不炸。IPC 只回 working-grid JPEG 预览（D3），落盘 PNG 不进 IPC。

**关键取舍**：
- `downsample=0`（自动）：命令层按 `ceil(长边/2048)` 选整数因子——Q2 的"2K 级教学集"不绑机型，由生成参数承担；现场拍板后可预生成固定数据集。
- 底图两档：`median`（实拍条图，默认，域差教学价值高）与 `pattern`（金属层掩码）；缺失是硬错误（与查看器的 Missing 语义相反——生成器没有理想图就无从谈起）。
- 真值范围（派生模式）：平移 ≤ 短边 5%、θ ≤ 1.5°、scale 1±1%——刻意保守，M2 必须能解开它们。
- UI 入口（D2 约束下）：Align/ROI 视图工具栏「🧪 案例生成」抽屉，覆盖在 stage 上，复用当前模型/侧；真值侧栏默认隐藏一键揭示——M6 出题模式的"揭示"交互原型。

## 13. M2 相位相关 MVP（2026-10-05，`align::phase`）

`PhaseCorrelateAligner` = `trait Aligner` 第一个真实现。M2 验收三条全过。

**实现要点（与设计稿 §15.1 骨架的差异）**：
- 骨架的 1D FFT（长度 w*h）是示意代码，实际是**正确的 2D FFT**——rustfft 只有 1D 规划器，2D = 行变换 + 列变换两遍拼装（`to_frequency`/`inverse_2d`）。
- 加了 **Hann 窗**（骨架没有）：FFT 相关是循环卷积，边界内容会绕回与对侧边相关，窗把边缘压到零后位移峰才干净。
- **PSR**（骨架没有）：`(peak − μ)/σ`，排除峰周 11×11。周期图案的其他等高峰落在旁瓣区，把 μ/σ 拉高——**多峰歧义由此变成数字**而不是"看起来不对"。

**踩坑（真实付出一次调试）**：抛物线亚像素 `0.5(l−r)/(l−2c+r)` 的分母在**峰处是负的**（凹），曾被 `.max(1e-12)` 钳成正 → 平坦邻域分母 1e-12、分子非零 → 亚像素爆到 ±1e15。教训：**数值守卫要判零，不能改号**。

**符号约定**：互功率谱 `Fa·conj(Fb)` 的 IFFT 峰在 `−t mod N`（input = template 平移 t 时），实现取负后折叠半宽。这个符号不是推导出来的信任——是 M1 生成器契约单测（已知 tx/ty 的合成案例）钉死的，这正是"案例库 = 回归锚点"的设计意图。

**PSR ok 门 = 10 的标定**：干净案例 PSR 数十；σ=2 噪声+轻模糊仍在门槛上；σ=35+blur3+50% 遮挡才掉到门槛下。周期案例整周期偏移时 PSR 掉到干净的一半以下。阈值可调（结构体字段），M5 置信度体系再统一。

**教学点已按计划"记录不修"**：周期性结构（BGA 阵列）在整周期偏移下"锁定在 k·周期"与"锁定在 0"同样合理——单测断言了"要么锁错要么诚实拒判"，这个行为本身进 M4/M6 教材。

**真值对比的 translation_only 标志**：`align_run` 返回求解值 vs 真值的误差；真值带 θ/s 时残差包含 M2 看不到的旋转/尺度部分（误差界 = 平移底噪 + 半对角线×(|θ|+|s−1|)，有单测），前端在揭示真值时明确标注"M3 解决"——不让学生把域限制当成 bug。

**M3 入口（spike 待做，≤1 天）**：(a) 纯 Rust ECC 自实现 vs (b) opencv crate vs (c) 金字塔相位相关加强；现有 `warp_transform`/PSR/亚像素骨架可直接复用。红绿 anaglyph 叠加已用 CSS 先行（对齐区域呈黄色），M3 三模式（红绿/差异/闪烁）在此之上扩展。

## 14. M3 精对齐（2026-10-05，`align::ecc`）— 两个教科书级踩坑

Spike 拍板 **D7：(a) 纯 Rust 自实现 ECC**（GN 相似变换 4 自由度）+ 相位相关粗初值 + [4,1] 两级金字塔。opencv 排除（Windows 构建链违背 D1、黑盒不可教学）；Fourier-Mellin 精度不足降级为粗层思想吸收进金字塔。`phase_translation` 从 M2 aligner 中抽出供管线复用。

**设计要点**：GN 的 warp 模型 `W(x) = c + s·R(θ)·(x−c) + t` 与生成器前向**同式**——解出即真值，无约定桥接。零均值/单位方差归一化吃掉 gain/offset；每迭代记录 Pearson 相关曲线（`r = 1 − SSE/2N`，两条零均值单位方差信号）供 M4 展示；OK = 粗层 PSR 门 **且** GN 收敛（迭代上限耗尽 = 不可信）。

**踩坑一（本日最大收获）：`solve4` 的行交换是假的。** 扁平化 `[f64;16]` 矩阵做部分主元消元时写成了 `a.swap(col, pivot)`——这交换的是**两个标量**（第 col 和第 pivot 个元素），不是两行。主元消元从未真正执行，反而每次破坏矩阵：GN 从真值出发第一步就系统性漂移、正反馈发散（相关 0.89→0.53→震荡）。调试路径值得记录：曲线测试发现第一步崩 → 临时 probe 从真值起步迭代打印 → 发现 b 在真值处非零且步长方向恒错 → 数值雅可比有限差分验证模型与函数不符 → 逐段排查后锁定 solve4。**教训：数值求解器必须单测"需要主元"的系统**（对角占优的系统不交换行也能解对，bug 完全潜伏）——现已入回归（`solver_handles_pivoting_and_singular_systems`）。

**踩坑二：二值图像上 GN 的梯度折点问题。** 我们的图是掩码/锐利边缘，双线性 warp 的 SSD 面是分段二次、在整数位移处有折点。中心差分梯度是"左右坡平均"，在折点处与真实单侧导数可差数倍（有限差分实测 ~2.5×）→ 一阶模型失效 → GN 步长方向错误。这也是 OpenCV ECC 等实现默认输入平滑的原因。**解法：GN 前对两图 σ=1 高斯平滑再求导**——梯度场与采样函数在亚像素尺度一致，收敛立刻正常（0.96→…→0.9999999 六步收敛）。

**层级细节**：金字塔层间真值换算只缩放平移（θ/s 无量纲直传）；warp 出画布的像素跳过不计入法方程；warp 后零填充带使两图全局均值/方差略有差异（常数残差偏置）——256px 测试图上可测、真实案例可忽略，M4 若需要可改用排除边界的统计。

**M3 验收全过**：旋转/尺度案例 θ≤0.1°、s≤0.2%、平移≤0.5px；4°/3% 大形变由金字塔 1/4 层吸收（超出派生真值范围，证明粗层在做实事）；相关曲线改善且收敛。三模式叠加（红绿 anaglyph / 差异 `mix-blend-mode: difference` / 闪烁 3Hz）纯 CSS 实现在 `AlignCaseLab`，无 canvas 依赖。

## 15. M4 管线单步拆解（2026-10-05，`align::steps`）

"白盒化是教学内容本身"的落地：管线重跑一遍但每个 stage 交出证据。

**产物设计**（`StepOut { id, title, subtitle, numbers, curve, images }`，≤1024px JPEG 预览）：
- **① preprocess**：双图预览 + 均值/σ——为 ECC 的归一化铺垫；
- **② phase**：**互功率谱相位角灰度图**（关键教学点：幅度归一化后幅度处处为 1，位移信息全在相位里——所以可视化的是 `arg` 不是模）+ **相关面 √ 压缩图**（峰比噪底高几个数量级，线性映射会全黑）+ 整数峰/解出平移/PSR 数值；
- **③ ecc**：金字塔层级、迭代数、收敛标志、最终相关系数、**相关曲线**（M3 里埋的钩子在此消费）、粗层预览图；
- **④ result**：warp back 对齐图 + |差异|×8 放大图——"差异图越黑越齐"的目检判据。

**讲解与证据分离**：三档讲解（🟢直觉/🟡数学/🔴代码）文案放在前端 `EXPLAINS` 常量，按步骤 id 键控；后端只出图像/数值/曲线。理由：讲解是教学编辑物（会频繁改措辞、加语言），证据是算法产物（跟代码走）——两者变更频率不同，不该绑在一个结构里。

**phase.rs 重构**：`correlation_surface` → `cross_power_with_surface`，同一次 FFT 返回 `(频谱, 相关面, fw, fh)`——相位角图和相关面图必须同源，否则教学时"谱上的特征在相关面里找不到"。

**遗留（问题点）**：设计稿的"参数滑块实时反馈（改噪声/角度立即看 PSR 变化）"需要秒级重生成案例；当前每次生成都从共享重新解码底图（大条图秒级起步）。待做：后端按 (machine,model,side,base) 缓存解码后的底图灰度缓冲（~4MB/张，LRU 2-4 张无压力），滑块反馈与 M6 出题的批量生成共用该缓存。已用"改参数→重新生成→看 PSR"的一键流顶替。

## 16. M5 基准点校验 + 置信度（2026-10-05，`align::fiducial`）— 三个教学级踩坑

`trait Aligner` 之外的第三层：**校验层**——"变换可信吗"由独立证据回答。

**最终形态**：Shi-Tomasi 选点（结构张量最小特征值，K=9）→ 以 M2 平移解为先验做 ±12px 局部 NCC（含抛物线亚像素）→ Umeyama 相似变换（nalgebra SVD，M5 首落地）+ RANSAC（2 点最小采样 + 3 轮重拟合）→ 置信度四指标 → OK/人工/NG。

**踩坑一：方差选点选中的全是长直边。** 第一版按窗口方差选 patch——方差最高的恰是长直边（白/黑边界带），而 NCC 沿边滑动分数几乎不变：实测在错的滑动位置拿到 **0.996** 的高分（探针数据：期望位移 1.35px、实际锁到 11px 外）。选点器的正确指标是**结构张量最小特征值**（Shi-Tomasi）：角点（十字/L/块角）两个方向都有梯度 → min-eig 大；直线边只有一个方向 → ≈0。这也是跟踪领域"good features to track"的标准答案。

**踩坑二：全图粗搜对自相似内容不可救药，基准点验证必须带先验。** 中间版本曾试图用"自匹配第二峰显著低于主峰"做独特性预过滤——对稀疏二值内容依然脆弱（标记沿自身臂滑动的自重叠就在排除半径边缘）。最终设计改为**先验局部验证**：全局解算（M2/M3）给出预测位置，基准点只在预测邻域内确认——真机也是这个流程（粗定位后校验 MK）。副产物：距离一致性指标因此有意义——它度量"局部确认点对的间距 vs 先验间距"，尺度差（先验看不见的）直接表现为比值偏离 1。

**踩坑三：Umeyama 的 SVD 方向约定。** 协方差按 Σd·sᵀ 累积、SVD = U D Vᵀ 时，把 src 转到 dst 的旋转是 **R = U·S·Vᵀ**（v 绑定的是 Vᵀ！）。第一次写成 V·S·Uᵀ（方向反了）——角度镜像、幅度检查全过、只有符号测试能抓。**精确合成用例（已知 θ=12°）+ 有限差分探针**是锁定这类 bug 的唯一手段。

**置信度体系（阈值全可配置，命令传参覆盖默认）**：
- NG：有效点 < 3 / 内点 < 3 / 平均 NCC < 0.5 / 残差 RMS > 3px / 距离比偏离 1 > 0.005；
- 人工：PSR < 10 / NCC < 0.85 / 残差 RMS > 1px；
- 其余 OK。

**验收**：尺度差案例（s=1.02，平移先验）mean_ratio ≈ 1.02 被正确 flag、判级非 OK；干净案例 ratio ≈ 1.0000 判 OK；RANSAC 在 9 点中剔除 1 个人为污染点后拟合仍达 θ<0.15°/s<0.3%。**遗留**：`residual_rms` 在 0 内点时为 ∞（serde 会序列化为 null——前端按 NG 显示）；距离一致性的比值噪声随 NCC 亚像素精度改善，真实大网格上 scale_tol 可能需要按基准点分布重标。
