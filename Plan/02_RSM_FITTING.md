## 1. 模型形式

### 编码空间（拟合就在这里做）

```
y = β₀ + β₁x₁ + β₂x₂ + β₃x₃
      + β₁₁x₁² + β₂₂x₂² + β₃₃x₃²
      + β₁₂x₁x₂ + β₁₃x₁x₃ + β₂₃x₂x₃
```

x ∈ {−1, 0, +1}，共 **10 个系数**。

**为什么必须在编码空间拟合（D3）**：若直接用 0~1024 的原变量，x² 项的量级是 10⁶，
x 项是 10³，设计矩阵的条件数会大到让 `lstsq` 的有效位数损失严重，同一个物理模型会
解出不同（甚至符号相反）的系数。编码后所有项都在同一量级，数值稳定。

### 实变量 ↔ 编码变量换算

```
xᵢ = (vᵢ − cᵢ) / hᵢ          cᵢ = (lowᵢ+highᵢ)/2,  hᵢ = (highᵢ−lowᵢ)/2
```

### 1.1 编码基准从哪来（量程标定后的关键改动）

**`cᵢ`/`hᵢ` 不再是写死的 512**，改为**从每色设计点的 v 列反推**：

```
lowᵢ  = min(v_i over 该色 design 行)      → 设计点上 u_i = −1
highᵢ = max(v_i over 该色 design 行)      → 设计点上 u_i = +1
cᵢ = (lowᵢ+highᵢ)/2,  hᵢ = (highᵢ−lowᵢ)/2
```

**为什么反推而不是让用户传配置：**
1. **数据自描述**：设计点的 min/max **就是** low/high（BBD 每轴必取 ±1 档），
   从数据拿基准永远与数据一致，不存在"配置和数据脱节"这类静默错位；
2. **零迁移**：旧数据（固定 512 档位）反推出 c=512/h=512，与旧行为逐位一致，
   向后兼容不需要任何分支；新档位（如红光 0/1/2）自动正确；
3. **可校验**：反推后断言设计点编码 ∈ {−1,0,+1}（±1e-9），等距被人为破坏
   （mid ≠ 算术中点）会立刻报错而不是静默产出错误模型——这是 Plan/01 §2.4
   等距约束在拟合端的最后防线。
4. 双保险：向导 CSV 头部/Excel meta 写有档位时与之交叉核对，不一致则报错。

### 导出给 UI 的形式（二选一，D4 建议两者都出）

**方案 A（推荐）：UI 直接用编码形式。**
UI 里把用户输入按 `coding`（逐轴 c/h，来自模型档位）做一次线性变换，再套 10 项公式。
好处：JSON 里存的系数与拟合结果**逐位相同**，无需二次变换，不会引入换算误差。

**方案 B：把系数展开回实变量（供人阅读/Excel 复算）。**
把 `xᵢ = (vᵢ − cᵢ)/hᵢ` 代回并展开同类项，得到 `y = a + bᵢvᵢ + cᵢᵢvᵢ² + dᵢⱼvᵢvⱼ`。
脚本同时输出这组系数并**回代抽查**（在若干点上比较 A/B 两式的结果差 < 1e-9），
以防人工核对时对不上号。
> 窄量程档位（如 0/1/2）下展开系数会非常大（h=1 → 1/h²=1）——这是正常的，
> 不是 bug；给 UI 消费的是**方案 A 的编码系数**，方案 B 只用于人工核对。

## 2. 拟合步骤

```
读取 samples.xlsx (design sheet)
  → 剔除 note 标记为异常的运行（记录原因，不要静默丢弃）
  → 用 gv_median 作响应 y
  → 构建设计矩阵 X（15 × 10：常数项 + 3 + 3 + 3）
  → β = lstsq(X, y)            # numpy.linalg.lstsq，rcond=None
  → 计算质量指标                # 见 §3
  → 用 verify sheet 做独立检验   # 不参与拟合
  → 写 light-model.json + report.md
```

**实现要点**
- 只用 `numpy` + `openpyxl`；**不引 sklearn**（10 个系数的 OLS 用 `lstsq` 一行就够，
  少一个依赖少一份环境问题）。
- `lstsq` 而非 `inv(X'X)`——设计矩阵在极端情况下可能接近奇异。
- 若同时存在多个中心点，用它们的方差做纯误差估计（pure error），
  再据此跑 **lack-of-fit F 检验**；点够就做，不够就在报告里注明"未做"。
- 可选：对 β 做 t 检验拿 p 值（需要手写 `(X'X)⁻¹` 对角元 + 残差方差），
  或者干脆用 `statsmodels` 只在**离线分析**时跑一次。生产脚本保持零依赖。

## 3. 质量指标（必须全部写进报告）

| 指标 | 公式/说明 | 门槛 |
|---|---|---|
| R² | `1 − SS_res/SS_tot` | **≥ 0.98** |
| 调整 R² | 惩罚项数（10 个参数，自由度 15−10=5） | ≥ 0.95 |
| RMSE | `sqrt(SS_res/df)`，df = 15 − 10 = 5 | 越小越好，与 GV 量程一起看 |
| 最大残差 | `max|y − ŷ|` 在设计点上 | 报告值 |
| **验证集最大相对误差** | `max|y_v − ŷ_v| / y_v`（5 个点） | **≤ 5%** |
| 残差图 | 残差 vs 拟合值、残差 vs 每一个 xᵢ | 无明显喇叭口/弯曲 |
| Lack-of-fit | 中心点纯误差 F 检验 | p > 0.05（不显著 = 模型够用） |

> **自由度警告**：15 个运行点拟合 10 个参数 → 只剩 **5 个自由度**。这意味着 R² 天生容易虚高，
> 所以**验证集误差比 R² 更可信**，两者都要看。若 R² 很高但验证点误差很大，说明过拟合，回阶段一加密。

## 4. 输出：`light-model.json`

```jsonc
{
  "schemaVersion": 1,
  "id": "FM1/6ST2001Q01/Red",            // machineId / modelName / channel
  "machineId": "FM1",
  "modelName": "6ST2001Q01",
  "channel": "Red",
  "lightLabel": { "x1": "0deg", "x2": "30deg", "x3": "60deg" },
  "inputRange": { "min": 0, "max": 1024 },
  "activeAxes": ["x1", "x3"],            // 参与模型的轴；不在其中 = 禁用轴（2026-09-23 实装）
  "fixedAxes": { "x2": 0 },              // 禁用轴固定值——预测的运行假设，UI 必须显著标注
  "levels": {                            // 每轴标定档位 [low, mid, high]；禁用轴 = null
    "x1": [0, 1, 2],                     // 未标定轴 = [0, 512, 1024]
    "x2": null,
    "x3": [0, 7, 14]
  },
  "coding": {                            // 仅活跃轴，由 levels 唯一决定
    "x1": { "center": 1, "half": 1 },
    "x3": { "center": 7, "half": 7 }
  },
  "responseUnit": "GV",
  "coefficients": {                      // 只含活跃轴项（k=3 → 10 项；k=2 → 6 项；k=1 → 3 项）
    "b0": 0.0,
    "b1": 0.0, "b3": 0.0,
    "b11": 0.0, "b33": 0.0,
    "b13": 0.0
  },
  "expanded": {                          // 展开到实变量（仅活跃轴；仅阅读/复算）
    "a": 0.0,
    "a1": 0.0, "a3": 0.0,
    "a11": 0.0, "a33": 0.0,
    "a13": 0.0
  },
  "quality": { "r2": 0.0, "r2Adj": 0.0, "rmse": 0.0, "maxResidual": 0.0,
               "verifyMaxRelErr": 0.0, "nPoints": 15, "nCenter": 3, "doF": 5 },
  "fittedAt": "2026-09-23T00:00:00Z",
  "dataSource": "samples.xlsx"
}
```

**系数键名固定、按活跃轴裁剪**：UI 侧按 `activeAxes` 驱动求值（只取存在的键）。
键名不一致会静默算错，所以 JSON 里**不用数组**（数组容易插错位置），用具名键。

**禁用轴的语义**：`fixedAxes` 里的值是模型的**运行假设**——预测仅在禁用轴保持
该值时有效。UI 必须把禁用轴显示为不可调（或固定值展示），并防止用户改动。

**`levels` 是 UI 的输入边界**：阶段三的滑条范围、外推警告都从 `levels` 取
（见 Plan/03），**不要**用 `inputRange`（那是驱动器名义上限，可能整体饱和）。
`coding` 由 `levels` 唯一决定，两个都存是为了让 UI 免算术、报告可复核。

## 7. 验收标准

- [ ] 脚本在只有 `numpy` + `openpyxl` 的环境下能跑通（无 sklearn / statsmodels 硬依赖）。
- [ ] R² ≥ 0.98 **且** 验证集最大相对误差 ≤ 5%（两者都满足才算过）。
- [ ] 报告里给出了残差图，且残差没有明显结构（无喇叭口、无弯曲）。
- [ ] JSON 能被 UI 的 TS 类型原样解析（字段名/类型与 §4 完全一致）。
- [ ] 展开到实变量的系数经回代抽查，与编码形式结果差 < 1e-9。
- [ ] 同一份输入重复运行两次，JSON 逐字节相同（确定性）。
- [ ] **编码反推正确**：对档位 `[0,1,2]` 的轴，设计点编码恰为 {−1,0,+1}；旧格式数据
  （固定 512）反推出 c=512/h=512，与改动前结果逐位一致（回归测试）。
- [ ] 档位与数据不一致（如 meta 写 0/1/2、数据里出现 512）时**报错**而非静默拟合。
- [ ] 模型中任一轴的设计点 GV 全部饱和（≥阈值）时，明确拒绝该轴进入拟合并给出
  "回阶段一重新标定"的指引，不允许产出全平台模型。

## 8. 常见失败与处置

| 现象 | 可能原因 | 处置 |
|---|---|---|
| R² 很高但验证点误差 > 5% | 过拟合 / 设计点太稀疏 | 回阶段一加点到 17 或 20 |
| 某个 β 的置信区间跨越 0 且很大 | 该项不显著 | 可选做模型缩减（删项重拟合），删项后必须重跑验证 |
| 残差随某个 xᵢ 呈 U 形 | 二次不够，存在三次效应 | 升级到三次项或分区间建模 |
| 中心点三次读数方差很大 | 读数噪声 > 模型效应 | 增加每点读数次数、取中位数，或检查光源稳定性 |
| 所有 β 都接近 0 | 三路光没有真正参与 / 通道选错 | 核对 `meta.channel` 与实际打光的通道 |
| 该轴设计点 GV 全为 255（或全相同） | 档位落在饱和平台区（量程未标定/漂移） | **拒绝拟合**，回 Plan/01 §2 重新标定该轴；数据在本窗口零信息，任何算法都救不回 |
| 编码断言失败（设计点 ≠ ±1/0） | 档位与数据脱节 / mid 不是算术中点 | 核对档位表与运行单实数列；违反等距约束的档位无效，须重新生成运行单 |
