Usage: ① drop LightSpec.xml (one file holds every light), ② drop one InspectionSpec.xml — or the whole INSPECT_SPEC folder: only the exactly-named spec files are read (a vendor copy InspectionSpec - 복사본.xml, AISpec.xml, Application.xml, … are ignored), the entries are listed as TOP/LIGHT1 and sorted TOP → BOTTOM, LIGHT0 → LIGHT1 → LIGHT2, and the first one is parsed → set Model Name, Side (TOP / BTM) and Light (1/2/3 → the code's LIGHT0/1/2, which is the <Page> used for the 조명 축) and, optionally, a base path (the export folder; Chrome writes straight into it) → Parse Specs → the Param: <SIDE> - <LIGHT> tabs show the parameters we need in the Parameter_Template.xlsx layout (RED / GREEN / BLUE values from the XML, GV row left for manual measurement) → type the GV values if you have them.
Two workbooks come out, named from the three inputs (<Model>_<SIDE>_LIGHT<n>_...):
• Export LightSpec + GV Excel → <Model>_<SIDE>_LIGHT<n>_LightSpec.xlsx — the parameter sheet with the GV rows (filled from the loaded template when there is one) plus the LightSpec / LightSpec Grouped listings.
• Export InspectionSpec Excel → <Model>_<SIDE>_LIGHT<n>_InspectSpec.xlsx — the InspectionSpec listing and the comparison.
Export reference (dict) writes Summary + the dictionaries on their own (optional). Export Sheet CSV writes the current tab.
② Optional: drop SpecParameter.xml / SpecTreeNode.xml to override the built-in dictionaries. Double-click a file name to rename it. Everything runs locally in your browser — nothing is uploaded.
Reference: SPEC_REFERENCE.md (files, key-value dictionaries, XML schemas) and PARAMETER_TEMPLATE_NOTES.md (template layout, required parameter set, open points) next to this file.
